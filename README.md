# MNetLinckGateway — шлюз MNet

Шлюз сети MNet гипервизора Murphy. Модель — **узел → линк → узел**: шлюз не особая сущность, а обычный
узел MNet с несколькими линками, который пересылает пакеты по `DstNode`. Линк в пакет не пишется, следующий
линк узел выбирает по своей таблице «узел → линк». Описание сети — `Prj Doc/mnet.txt` в репозитории ядра,
формат пакета и протокол маршрутов — `src/CommonInc/MNet.h`.

```text
             COM                          TCP
  hv (1.1) ─────── шлюз (1.5) ─────────────────── отладчик dev (1.3)
                       │      ─────────────────── другая программа (1.50)
                       └── local ──────────────── контроллер стенда (1.6)   (в Dbg)
```

## Состав

| Каталог | Что |
|---|---|
| `core/MNode.{h,c}` | Переносимый узел MNet на C11: линки, таблица маршрутов, пересылка, endpoint'ы, служба route. Без ОС, потоков и malloc — вся память в структуре `MNODE`. |
| `app/` | `mnetgw` — шлюз как отдельная программа: COM-порт (или TCP-клиент к последовательному порту QEMU) и TCP-сервер для узлов. Платформа — `platform_win.c` (Win32, Winsock) или `platform_posix.c` (termios, сокеты). |
| `tests/test_mnode.cpp` | Тесты узла без Qt: несколько узлов в памяти, соединённых «проводами». |

Dbg берёт отсюда только `core` (через `add_subdirectory`, переменная `MNET_GATEWAY_DIR`): его `MNetRouter` —
обёртка Qt над `MNode`, поэтому шлюз в Dbg и `mnetgw` — один и тот же код.

## Как узнаются маршруты

Служба route (`MNET_ENDPOINT_ROUTE`) — у каждого узла. Маршрутами обмениваются только соседи: запросы идут на
`MNET_NODE_LINK` («сосед по линку», дальше не пересылается), ответ — тем же линком.

- `REGISTER` — «я и эти узлы доступны через меня»; `FULL` — список полный, `NOTIFY` — присылать изменения.
  Ответ — таблица отвечающего, так что один запрос меняет маршруты в обе стороны.
- `GET` — таблица соседа страницами (discovery).
- `UNREGISTER` — узлы больше недоступны.

hv регистрируется у шлюза сам по доверенному внешнему линку (`COM1`) и объявляет свои VM. Программа на TCP
регистрируется своим адресом; старая, без службы route, узнаётся по первому пакету. Отключение снимает маршруты,
и подписанные соседи (hv, отладчик) узнают об этом сразу — рассылка уходит раньше, чем шлюз перешлёт первый
пакет нового узла.

Политика линка в `MNode` (`MNODE_LINK_*`):

| Флаг | Смысл | Где |
|---|---|---|
| `TRUST` | сосед может объявлять узлы за собой | COM, TCP, локальные линки |
| `LEARN` | сосед без службы route узнаётся по первому пакету | TCP-подключения |
| `ADOPT` | неизвестный источник — узел за соседом (объявление потерялось на линии) | COM |
| `ANNOUNCE` | узел сам регистрируется у соседа и берёт его таблицу (1, 2, 4, 8 с, потом раз в 15 с) | узел → шлюз, hv → внешний линк |
| `DEFAULT` | маршрут по умолчанию; источники с него не проверяются | узел → шлюз |

Пока hv не зарегистрировался, шлюз предполагает, что за COM — hv (`bootstrap`, ключ `--com-neighbor`): так
работает и ядро без службы route.

## Запуск

```bash
mnetgw --com COM3 --listen 127.0.0.1:8890 -v
```

```bash
mnetgw --com tcp:127.0.0.1:8888 --listen 127.0.0.1:8890 -v
```

Второй вариант — к hv в QEMU (`-serial tcp:127.0.0.1:8888,server=on,wait=on`). Байты вне пакетов с COM (загрузчик,
EarlyIo, паника, Linux стенда с `[TEST_STAND_READY]`) идут в stdout и клиентам порта сырых байтов (`--raw`): оттуда
их берёт Dbg в режиме «через шлюз». Сообщения шлюза — в stderr; `-v` печатает таблицу маршрутов при каждом изменении.

| Ключ | По умолчанию | |
|---|---|---|
| `--node N.N` | `1.5` | адрес шлюза |
| `--com PORT` | — | `COM3`, `/dev/ttyUSB0` или `tcp:host:port` |
| `--baud N` | `115200` | скорость COM-порта |
| `--listen HOST:PORT` | `127.0.0.1:8890` | TCP-сервер для узлов; `off` — без него |
| `--raw HOST:PORT` | `127.0.0.1:8892` | TCP-сервер сырых байтов COM: только чтение, живой поток, до 8 клиентов; `off` — без него |
| `--com-neighbor N.N` | `1.1` | кто предполагается за COM до регистрации; `none` — никто |

Адрес у каждого узла свой. Если узел (или узел за ним) объявляет адрес, который уже занят за другим линком,
шлюз его не принимает и пишет `node N.N refused: address is taken behind another link` — пакеты этого узла через
его подключение отбрасываются. Так выглядит, например, второй Dbg с тем же адресом шлюза (1.7) или шлюз Dbg с
адресом самого `mnetgw` (1.5). Пакеты с чужим адресом отправителя — `packets from N.N dropped`; повторы обоих
сообщений минуту не печатаются.

## Перенос на другую платформу (ESP32, MCU)

`core/MNode.c` переносится как есть. Нужно:

1. Держать `MNODE` (≈ 30 КиБ при размерах по умолчанию; меньше — через `MNODE_MAX_LINKS`, `MNODE_MAX_ROUTES`,
   `MNODE_MAX_ENDPOINTS`, `MNODE_LOCAL_QUEUE`) и по `MNET_PARSER` на каждый потоковый линк.
2. Для каждого транспорта (UART, TCP lwIP, ...) — `MNODE_LINK_OPS.Send`: принять пакет целиком в свою очередь
   или ответить `MNODE_TX_FULL` / `MNODE_TX_DOWN`; принятые байты отдавать в `MNode_InputBytes`.
3. Подъём и падение транспорта — `MNode_SetLinkUp`, новое и закрытое подключение — `MNode_AddLink` / `MNode_RemoveLink`.
4. Звать `MNode_Poll(миллисекунды)` раз в 10–100 мс. Все вызовы — из одного потока.
